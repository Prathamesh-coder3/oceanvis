# OceanVis — 2D/3D + Stability Upgrade

## Delivered improvements

### 2D Ocean Map
- Replaced the old static hotspot/patch presentation with a model-field layer driven by `/api/demo/model-slice` for the selected variable, depth and time.
- Added a cleaner ocean-data overlay with variable-aware color scaling, directional current vectors and observation markers.
- Corrected geographic pointer-to-coordinate conversion while the SVG uses `preserveAspectRatio="xMidYMid meet"`.
- Corrected drag direction so the map follows the pointer naturally.
- Added functional region presets, zoom, reset, graticule toggle, measurement workflow, scale cue and north-arrow HUD.
- Added a visible model-field legend and loading state.

### 3D Earth
- Upgraded the globe presentation with an API-backed model field rather than only fixed hotspot markers.
- Added variable-aware model colors, depth-slice / volume / isosurface visual cues, scientific graticule lines and current vectors.
- Kept a local Earth texture plus a WebGL fallback so the globe remains visible while assets load.
- Fixed mouse/pointer hit-test typing and synchronized zoom/reset state with the active regional context.
- Ensured model field, time, depth and opacity changes trigger fresh rendering.

### Shared controls / behavior
- Layer opacity is now shared state, so the Data Layers slider actually controls the visualization.
- Dataset metadata now hydrates the shared variable/time/depth axes on startup.
- Right-panel variable tabs now change the selected visualization variable.
- Observation popup profile typing and signed latitude/longitude labels were corrected.
- Fixed an API request-dedup race where an older aborted request could remove the newer request from the pending map.
- Corrected the `/api/data-status` demo observation count from 28 to the 16 observation records actually generated by the demo service.

### Launch reliability
- Maven packaging was simplified to use the already bundled React SPA in `src/main/resources/static`, avoiding a second Node/npm build toolchain during normal Spring Boot packaging/launch.
- The final archive excludes `node_modules`, stale `target/`, and the transient `.backend-port` file so an old/incomplete build cannot silently override the updated source/static bundle.
- The progressive enhancement script is included in both frontend public assets and Spring static resources. It provides the stronger 2D/3D presentation for the currently packaged static SPA while avoiding duplicate rendering after a fresh React rebuild.

## Validation completed

- Parsed/transpiled all 28 TypeScript/TSX source files with the installed TypeScript compiler: 0 syntax diagnostics.
- `node --check frontend/public/oceanvis-upgrade.js`: passed.
- `pom.xml`: valid XML.
- A full `npm ci && npm run build` could not be completed in this sandbox because the required packages are not available locally and package downloads are unavailable here.
- A full Maven package/run could not be executed because Maven is not installed in this sandbox.
- Therefore the archive is source-checked and static-asset-checked, but not claimed as a freshly produced production JAR from this environment.

## Data mode

The application remains in DEMO mode. The ocean model fields and observation records are synthetic prototype data; this upgrade does not claim live INCOIS/ARGO/GLIDER/CTD/BGC ingestion.
